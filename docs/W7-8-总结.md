# W7–8 自动化流水线阶段记录

## 当前结论

W7–8 的版本探测、隔离下载、提取与继承、SAFE 复检、候选预翻译、自动 PR、发布失败处理和支持矩阵生成已经落地。真实历史版本演练、SAFE→DANGER 合成场景、机器人 PR 和 EOL 生成四项 DoD 均已通过。

当前生产阻塞不是流水线故障：CLI `2.1.220` 已从最后一个 JS 版本的 AST surface 切换为原生二进制 surface，直接继承率为 `0.00%`。流水线按 80% 门槛停止，没有调用 LLM、没有生成 3 万条候选的常规语料 PR，也没有降低门槛。阻塞由 [issue #2](https://github.com/skxxxkx666/claude-zh-bilingual/issues/2) 跟踪，进入 W9–10 解决。

## 交付内容

- `.github/workflows/watch.yml` 每 6 小时运行，并支持 `update-if-needed` 与 `historical-drill` 手动触发。
- CLI 版本来自 [npm registry 官方包元数据](https://registry.npmjs.org/@anthropic-ai%2Fclaude-code/latest)。
- Desktop 使用 [Anthropic 官方 Windows latest 下载入口](https://claude.ai/api/desktop/win32/x64/setup/latest/redirect)；入口不返回可解析版本或当前地区不可访问时标记 `unavailable`，不猜测版本、不触发更新。
- 上游包只用 `npm pack --ignore-scripts` 下载到隔离目录；tar 成员逐项校验，拒绝路径穿越、链接和特殊文件。
- JS 包走 AST extractor，原生包走 binary extractor；两者都复用现有分类器。
- 继承按 `unit_id`、source 和 surface 三重检查。占位符写法或 surface 变化时清空译文并重新分类。
- 每次更新对所有 SAFE occurrence 重跑规则 1–5；命中 DANGER/FRAGILE 时立即降级、清空 `target` / `target_bilingual` / `verified_at` 并列入告警。
- 新上游内容只把 `R-UITEXT` candidates 持久化；DANGER、FRAGILE、长 prompt 和默认 UNKNOWN 不写入 corpus。
- 预翻译 prompt 每次直接从 `docs/SPEC.md` §8 的 fenced block 读取，替换两个 JSON 占位符，不维护第二份文案。
- GitHub Models 仅接收 UNKNOWN `R-UITEXT` candidates。返回内容先校验 ID、占位符和显示宽度，作为 `reviews/` 建议进入 PR，不会自动授予 SAFE。
- 自动 PR 正文固定包含新增、继承、降级告警、消失、风险清单和低置信度清单；添加 `automated` 标签，永不自动合并。
- 发布工作流在主分支相关变更后自动跑完整门禁；门禁通过且版本未发布时自动建 tag/release，已存在版本幂等跳过；任一失败自动开或更新 issue。
- `docs/support-matrix.md` 由脚本生成，按最近 3 个 minor 与 `cli@2.1.112` 最后一个 JS 版本规则标记支持范围或 EOL。

## 当前原生版本阻塞

对 CLI `2.1.220` 的只读压力验证得到：

- 原生包隔离解包成功，SHA-256 与 W1 只读样本一致。
- 提取 `1,713,378` 条 occurrence，峰值工作集约 `1.44 GB`。
- 新候选 `31,487` 条；368 个既有 ID 需要重分类，其中 363 个是 SAFE 降级告警；56 个旧 ID 消失。
- 因 AST surface 全部变为 `cli.binary.literal`，直接继承率 `0.00%`，低于 RUNBOOK 80% 门槛。

解决方式是在 W9–10 为原生二进制建立经过人工核验的 surface mapper，再分批审阅 changed-surface 与新增候选，最后对补丁副本执行 S1–S3。不能通过把所有 binary literal 重新标 SAFE、忽略 surface 变化或降低继承门槛来解除阻塞。

## 仓库设置

为允许机器人真正创建 PR，仓库启用了 GitHub Actions 的 `can_approve_pull_request_reviews` 开关。工作流默认权限仍为 `read`，只有 `watch.yml` 和 `release.yml` 显式申请所需写权限；现有工作流没有 review approval 或 merge 命令，也未启用自动合并。
