# W1–2 总结

## 结论

W1–2 的本地交付已完成：数据契约、核心算法、三类提取入口、风险分类器、CI 骨架和首份零译文语料均已落地。所有本地测试与 corpus 校验通过，未编写任何 patcher，也未给任何 unit 填写译文或授予 `SAFE`。

唯一尚未满足的 DoD 是“两个 workflow 在 GitHub 上实际跑通”。当前仓库没有 remote，无法产生真实的 GitHub Actions run；首次推送后必须先确认 `Tests` 和 `Validate corpus` 均为绿色，再进入 W3–4。

## 交付物

- `corelib/`：`normalize`、`extract_placeholders`、`unit_id`、`display_width`
- `schema/validate.py`：JSON Schema 与八类语义检查
- `extractors/js-ast/`：Acorn AST 单文件/目录提取
- `extractors/binary/`：ASCII/UTF-8 occurrence、字节偏移、字节长度与 PE section 上下文
- `extractors/locale-json/`：Desktop 扁平 locale catalog 提取
- `classifiers/`：按 SPEC §6 顺序匹配并输出三个队列
- `scripts/build_initial_corpus.py`：去重、排序、零译文 corpus 生成
- `corpus/cli/2.1.112.json`
- `corpus/desktop/1.18286.0.json`
- `.github/workflows/test.yml`
- `.github/workflows/validate.yml`

## 契约冻结前修订

M1 已指出 schema 与 SPEC 的占位符契约冲突，用户确认先修订再冻结。本阶段完成：

1. `placeholders` 保留出现顺序与重复项，不再要求数组元素唯一。
2. `${name}` 只识别一次，不再与 `{name}` 重叠计数。
3. `unit.schema.json` 的三条示例 ID、字节预算与显示宽度统一为核心算法实算值。
4. SPEC §1.3 的全部 ID 向量及重复/重叠占位符行为纳入单元测试。

抽查发现 candidates 中仍混有第三方运行时错误和内部诊断。为遵守 R2，不能把整个候选队列提交为“UI 原文”。首份 CLI corpus 只收录 M1 已人工确认的 5 条可见基准文案，并原样保留分类结果：

| risk | corpus units |
|---|---:|
| DANGER | 0 |
| FRAGILE | 1 |
| UNKNOWN | 4 |
| SAFE | 0 |

完整 candidates 留在被 Git 忽略的 `extracted/`，供 W5–6 人工审阅，不进入仓库。

### CLI 2.1.220（二进制）

对 265,720,480 字节 Windows PE 样本完成只读全量扫描，提取 1,713,378 条 occurrence。结果与 M1 探针一致，生产提取器额外记录 PE section 与 executable 标记。该输出只用于 T4 验证，保存在被忽略的 `extracted/`，不进入 corpus。

### Desktop 1.18286.0（locale catalog）

| 指标 | 分类前 | corpus 去重后 |
|---|---:|---:|
| 总数 | 435 | 406 |
| DANGER | 2 | 2 |
| FRAGILE | 6 | 4 |
| UNKNOWN | 427 | 400 |
| SAFE | 0 | 0 |
| candidates 队列 | 427 | — |
| excluded 队列 | 8 | — |

去重时合并 28 条重复 occurrence，并遇到 1 组规范化 ID 碰撞；生成器采用 fail-safe 规则，冲突时保留更高风险等级。Desktop 来源是应用自身 locale catalog，因此 406 条均属于 UI 原文，允许进入 corpus。

## 本地验证

```text
python -m unittest discover -s tests -v
Ran 22 tests
OK

python schema/validate.py corpus
validated 2 corpus file(s), 411 unit(s)
```

检查结果：

- SPEC §1.3 全部测试向量一致。
- AST、locale JSON 与 binary 提取器均有集成烟测。
- 分类器从不输出 `SAFE`，规则 6 只进入 UNKNOWN/candidates。
- 两份 corpus 均按 ID 排序，所有 unit 的 `target`、`target_bilingual`、`verified_at` 均为 `null`。
- `samples/`、`extracted/`、`node_modules/`、`.venv/` 和构建副产物均被忽略。
- patcher 目录只有占位文件，没有实现代码。

## CI 映射

`validate.yml` 调用同一 `schema/validate.py`，覆盖 PLAN §7.1：

1. JSON Schema
2. 占位符一致性
3. 显示宽度约束
4. glossary 术语一致性
5. 风险字段完整性
6. DANGER/FRAGILE → SAFE 的双人审批审计
7. 禁用词与 emoji 检测
8. 双语标注及中英混排格式

`test.yml` 在 Python 3.11 与 Node.js 22 下安装锁定的 Acorn 依赖，运行核心算法、分类器、corpus builder 与提取器集成测试。GitHub 官方 actions 也固定到具体 commit SHA，避免可移动标签带来的供应链漂移。
