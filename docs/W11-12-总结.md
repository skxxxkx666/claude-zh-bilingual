## 单文件 EXE

推荐方案为 .NET 8 Native AOT 引导器加官方 Node `22.23.1` payload。选择它的原因：

1. 保留已经完成 S1–S3 和 ConPTY 长测的 Node 行为；
2. 允许 Windows 从普通文件加载 `node-pty` 的 `.node`、DLL 和辅助 EXE；
3. 用户只下载一个 EXE，不需要安装 Node、npm 或 .NET；
4. 引导器只负责校验、释放、菜单和启动，不重复实现高风险补丁逻辑。

本地真实构建大小为 39,746,560 字节。首次运行在隔离缓存中释放 375 个运行
文件；构建阶段删除其他平台 prebuild、PDB 和编译源文件。内置 CLI `--help` 与
ConPTY 输入输出自检均通过，PTY 子进程退出码为 0。

完整方案比较与安全模型见
[`windows-launcher.md`](windows-launcher.md)。

## 构建与发布门禁

`.github/workflows/launcher.yml` 在 PR 上验证候选；合并后
`.github/workflows/release.yml` 在 Windows runner 重新执行同等门禁：

1. 使用锁定的 Node `22.23.1` 与 .NET SDK `8.0.421`；
2. 执行 Node 测试；
3. 运行 `scripts/build_windows_launcher.ps1`；
4. 验证启动器版本与 payload hash；
5. 从 EXE 运行内置 CLI `--help`；
6. 从 EXE 运行只读 `doctor --json` 并核对报告版本；
7. 从 EXE 加载 `node-pty`，启动真实 ConPTY 并验证 `PTY_OK`；
8. 把 EXE 与 `SHA256SUMS.windows` 交给同一工作流的 Release job；
9. Release job 复核哈希，并把 EXE、两个校验文件与 npm `.tgz` 发布为 prerelease。

本地构建只用于开发验证，禁止手工上传到 Release。
