# 任务:Claude 中文化项目 · M1 可行性勘测

你是本项目的技术勘测负责人。本轮任务是**纯调研**,目标是判断「Claude 中文化项目」在技术上是否可行、应走哪条路线。

## 一、硬性约束(违反任何一条即任务失败)

1. **绝对禁止修改本机已安装的 Claude Code**。你自己正运行在 Claude Code 上,修改它等于自毁。所有样本必须下载到隔离工作区分析。
2. **绝对禁止执行 `npm install -g`、`npm update`、`claude update`、`claude install`**,或任何写入全局 node_modules / Claude 安装目录的命令。
3. **绝对禁止修改 Claude Desktop 的任何文件**。需要分析时,先把 `app.asar` **复制**到工作区,只解包副本。
4. **本轮不编写任何生产代码**。只允许写一次性分析脚本,全部放在 `scripts/probe/` 下。
5. **不要把任何原程序代码、二进制、asar 内容提交进 git**,`.gitignore` 必须先建好。
6. 遇到需要 sudo / 管理员权限的操作,**停下来问我**,不要自行提权。

## 二、环境说明

先自行探测并在报告中记录:操作系统、架构、Node 版本、npm 版本、当前 Claude Code 版本与安装方式(npm 全局 / native installer)、是否安装了 Claude Desktop 及其版本。

跨平台注意:**不要依赖 `strings` 命令**(Windows 无此命令)。所有二进制字符串提取用 Python 实现,保证三端一致。

## 三、任务清单

### Task 0 · 建立隔离工作区

```
probe/
├─ samples/          # 下载的样本(gitignore)
├─ extracted/        # 提取产物(gitignore)
├─ scripts/probe/    # 一次性分析脚本(提交)
└─ report/           # 勘测报告(提交)
```

先写 `.gitignore`,把 `samples/` 和 `extracted/` 排除。

### Task 1 · 获取 CLI 的 JS 金标准样本

`v2.1.112` 是最后一个 JavaScript 构建版本,是唯一能做 AST 分析的 CLI 样本,用于冷启动语料库和验证风险分类器。

```bash
cd probe/samples
npm pack @anthropic-ai/claude-code@2.1.112
```

解包到 `samples/cli-2.1.112/`。记录:`cli.js` 是否存在、文件体积、是否 minified、是否可读。

**注意**:只用 `npm pack`(下载 tarball),不要 `npm install`。

### Task 2 · 获取 CLI 最新 native binary 样本

```bash
npm view @anthropic-ai/claude-code version
npm view @anthropic-ai/claude-code optionalDependencies
npm pack @anthropic-ai/claude-code@latest
```

从 `optionalDependencies` 中找出匹配本机平台的原生包(如 `@anthropic-ai/claude-code-darwin-arm64` / `-linux-x64` / `-win32-x64`),同样用 `npm pack` 单独下载该平台包。

记录:主包内容清单、`install.cjs` 的逻辑要点、原生二进制的路径与体积、文件类型(`file` 命令或读魔数)。

### Task 3 · 二进制字符串提取与明文率评估 ⭐ 核心判定

**这一步的结论决定 CLI 是否走二进制 patch 路线,是本轮最重要的产出。**

写 `scripts/probe/extract_strings.py`,要求:

- 以二进制模式读取,扫描连续可打印 ASCII 序列(长度 ≥ 4)
- 同时尝试 UTF-8 解码,识别非 ASCII 字符串
- 输出每条字符串的:内容、字节偏移量、字节长度
- 结果写入 `extracted/cli-binary-strings.jsonl`

然后做分类统计,回答这些问题:

1. 总字符串条数是多少?
2. 其中**形似 UI 文案**的有多少?判据:首字母大写 + 含空格 + 长度 4–120 + 不含 `/`、`\`、`::`、`_` 等标识符特征
3. 能否找到具体的已知 UI 文案?**必做验证**:搜索这些实际出现在界面上的文本
   - `Press Shift+Tab`
   - `auto-accept edits`
   - `Continue`
   - `Permission denied`
   - `Thinking`
   - `context left`
   - 以及若干 spinner 动词(如 `Photosynthesizing`)
4. 是否存在明显的 **bytecode 化 / 压缩** 迹象?(可读字符串占比极低、UI 文案完全找不到)
5. 抽取 30 条形似 UI 文案的字符串,统计它们的字节长度分布 —— 用于评估「等字节长度替换」的可行空间

**判定输出**(必须在报告中明确给出结论):

| 观测 | 结论 |
|---|---|
| 能定位到大量已知 UI 文案,且明文可读 | ✅ CLI C 路线(二进制 patch)可行 |
| 只能找到零星字符串,UI 文案大量缺失 | ⚠️ C 路线覆盖率不足,降级为可选增强 |
| 几乎找不到可读 UI 文案 | ❌ 放弃 CLI C 路线,资源全押 A + B |

### Task 4 · JS 版本 AST 分析与风险分类可行性验证

对 `samples/cli-2.1.112/cli.js` 做分析。文件约 13MB 且经过 bundle,先评估可行的分析手段(AST parse 是否会 OOM,是否需要流式/正则降级)。

需要回答:

1. 能否提取出全部字符串字面量?总数多少?
2. **能否识别出 tool description / system prompt 类字符串?** 这是 DANGER 类的主要来源。找找有没有超长(>200 字符)的完整英文段落,以及位于 schema-like 对象 `description` 字段内的字符串
3. **能否识别出被代码自身匹配的字符串?**(即 FRAGILE 类)搜索 `.includes(`、`=== "`、`.match(`、`switch` 附近的字符串字面量
4. 按前述三类做一次自动分类,给出各类占比
5. **抽样人工校验 20 条**,评估分类器准确率

同时提取所有含占位符(`{0}`、`%s`、`${`)的字符串,单独统计。

**判定输出**:自动风险分类的准确率是否达到可用水平(目标 ≥ 90%,且 DANGER 类无漏判)。

### Task 5 · Claude Desktop 勘测

先定位 `app.asar`(不要修改,只读):

- Windows:`%LOCALAPPDATA%\AnthropicClaude\app-*\resources\app.asar`,或 `C:\Program Files\WindowsApps\` 下的商店版
- macOS:`/Applications/Claude.app/Contents/Resources/app.asar`
- Linux:视安装方式而定

**复制到 `samples/desktop/` 后再解包**:

```bash
npx @electron/asar extract <复制来的app.asar> probe/samples/desktop/unpacked
```

需要回答:

1. 是否存在 i18n 资源目录?路径和文件组织形式是什么?
2. 支持哪些语言?**是否已存在 `zh-CN` 或 `zh` 相关资源位?**
3. key 的命名结构是怎样的?层级如何?总 key 数量约多少?
4. 是否存在 Statsig 相关的本地化资源?
5. **有多少 UI 文案没有进入 i18n JSON,而是硬编码在 JS chunk 里?** 抽样评估比例
6. 是否有语言切换的运行时开关?(搜索 `locale`、`i18n`、`language` 相关的配置读取逻辑)

**判定输出**:Desktop 的 i18n 基础设施是否完整到「填空即可」的程度。如果是,W3–4 的 Desktop 首发计划成立。
