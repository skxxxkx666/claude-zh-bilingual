## 冒烟测试

依据 `docs/SPEC.md` §5.1：

| 断言 | 结果 | 输出 |
|---|---|---|
| S1 `claude --version` | pass | `2.1.201 (Claude Code)` |
| S2 最小模型请求 | pass | `2` |
| S3 读取当前目录 `package.json` | pass | `claude-zh` |
| S2 原始环境对照 | fail | 未传递系统代理时返回 `403 Request not allowed` |

### 403 根因与处理

- `claude auth status --text` 显示 Claude Pro 登录态。
- 当前进程、用户和机器范围都没有 `ANTHROPIC_API_KEY`、`ANTHROPIC_AUTH_TOKEN`、`ANTHROPIC_BASE_URL` 或云提供商覆盖项。
- Claude 设置没有 `apiKeyHelper`，也没有代理环境变量。
- Windows Internet Settings 已启用一个本地回环系统代理，但 WinHTTP 和 Claude CLI 进程仍是直连。
- 未传递代理时 S2 返回 403；仅在单次子进程中设置 `HTTP_PROXY`、`HTTPS_PROXY` 后，S2 和 S3 立即通过。

因此阻塞来自 Claude CLI 未继承 Windows 系统代理，不是账号失效，也不是 A 层设置。验证没有永久修改代理、登录或凭证配置。

## 已知限制

Claude Code `2.1.201` 未注册中文 skill / command 文件名，因此阶段提示中的 `/压缩` 不能按示例落地。最终使用 `/zh-compact` 等 ASCII 标识符和中文说明，不把不生效的中文命令写入用户配置。
